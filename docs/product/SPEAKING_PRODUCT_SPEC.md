# ORENA — SPEAKING PRODUCT SPECIFICATION

Status: Human product specification
Languages: EN + ZH
Core idea: Speaking practice must connect to meaningful source material, not only a blank recorder.

## Main modes
Free response; pronunciation practice; Shadowing from Listening/Media; read-aloud from Reading; vocabulary/phrase review; speaking tasks generated from learner mistakes/current lesson.

## Shadowing handoff
Listening → Shadow this segment → Speaking opens the SAME asset/lesson/segment/reference text. Flow: play model → repeat → record → listen to self → retry → optional evaluation.

## Recording
Explicit microphone permission states, start/stop, visible recording, duration, own-take playback, retry/discard and truthful errors. Do not upload recordings unless the active evaluation feature requires it and policy allows it.

## Evaluation
When real evaluation exists, separate intelligibility, pronunciation, fluency, rhythm/stress, completeness and transcript match. Do not invent acoustic precision or infer a global CEFR/HSK level from one utterance.

EN may use phoneme/word feedback where supported. ZH shows Hanzi/Pinyin and tone feedback only if the evaluator truly supports tones.

## Task types
Repeat a line; answer a Listening question; summarize a clip; describe context; daily role-play; retell Reading; use saved vocabulary. No immersive romantic roleplay.

## Feedback
Actionable, learner-level appropriate: what was clear, what to retry, one or two highest-value targets, corrected model/example, replay model.

## Connected outputs
Useful mistakes may feed Library/Active Recall, pronunciation review, Writing prompts and future Speaking practice. No disconnected Speaking-only review silo.

## Acceptance
Recording + own-take playback + Shadowing handoff + EN/ZH + truthful evaluation/degraded states + persistence + web/native parity.

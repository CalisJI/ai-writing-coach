BECOMING — EDITORIAL TACTILE INTELLIGENCE
VISUAL CONTRACT

The attached BECOMING Light and Dark Visual Direction boards are the
APPROVED VISUAL BENCHMARKS for this product.

They are not moodboards.
They define the expected level of:
- visual quality
- contrast
- physical depth
- material treatment
- typography hierarchy
- composition
- spacing
- accent discipline
- overall refinement

Do NOT copy their literal demo layout.
Do NOT reproduce the exact sample screen.
Instead, transfer their VISUAL GRAMMAR to every new interface.

==================================================
CORE VISUAL IDENTITY
==================================================

The interface must feel:

EDITORIAL
×
TACTILE
×
INTELLIGENT
×
CALM
×
PRECISE

In one sentence:

A high-contrast editorial interface built from soft,
tactile digital objects.

Strong typography creates meaning.
Physical depth creates hierarchy.
Restrained color creates focus.
Intelligence remains quiet.

==================================================
1. EDITORIAL CONTRAST
==================================================

Every important screen must have a strong visual hierarchy.

Prefer:

DOMINANT STATEMENT
↓
short supporting context
↓
HERO EXPERIENCE
↓
evidence / supporting information
↓
secondary details

Avoid distributing equal attention across many components.

The main headline should feel substantially stronger than supporting text.

Important moments may use:
- large bold typography
- compact line-height
- high contrast
- short statements
- intentional negative space

The screen should feel composed like an editorial layout,
not assembled like a SaaS dashboard.

==================================================
2. SOFT PHYSICAL DIGITAL SURFACES
==================================================

Important UI objects must feel tactile.

Desired material:

- solid
- matte
- softly rounded
- refined
- lightly dimensional
- studio-lit
- physically plausible

Depth should come from the combination of:

1. tonal separation
2. subtle rim definition
3. directional light
4. ambient shadow
5. contact shadow
6. restrained material gradient when useful

Do NOT rely on a single generic box-shadow.

Do NOT use:
- excessive glassmorphism
- neon glow
- glossy chrome
- extreme neumorphism
- flat border-only cards

Important objects should feel like they are sitting on a surface.

==================================================
3. HERO PRESENCE
==================================================

Every major screen should have ONE clearly dominant visual object
or experience.

Examples:

- current learning bottleneck
- writing feedback module
- progress object
- mastery state
- learning journey
- language identity
- important evidence

Supporting components must visually recede.

Avoid four or more same-weight cards competing for attention.

Prefer:

[           HERO            ]

[ evidence ] [ evidence ]
[ secondary supporting data ]

over:

[card] [card] [card] [card]

==================================================
4. TONAL HIERARCHY
==================================================

The visual layers must remain distinguishable even without text.

Required hierarchy:

Canvas
↓
Section surface
↓
Primary surface
↓
Raised object
↓
Floating control
↓
Accent signal

Never create depth simply by stacking almost-identical gray surfaces.

Adjacent layers must be visibly different through:
- tone
- light
- material
- elevation

not only borders.

==================================================
5. ACCENT DISCIPLINE
==================================================

The interface is predominantly neutral.

Accent is intentionally scarce.

Warm orange is the primary visual signal unless another semantic
color is required.

Use accent mainly for:
- primary CTA
- active state
- important progress
- selected object
- significant insight
- small visual anchor

Do NOT apply accent to:
- every icon
- every title
- every border
- every metric
- every card

If everything is accented, nothing is accented.

==================================================
6. LIGHT MODE
==================================================

Light mode should feel:

- clean
- editorial
- tactile
- bright but not sterile
- warm-neutral
- highly legible

Use:
- warm off-white canvas
- near-black typography
- clean raised surfaces
- strong tonal contrast
- soft shadows
- sparse orange accents

Light mode is the primary visual expression for:
- Home
- Journey
- Progress
- Review overview
- Profile
- Library
- Reflection
- Milestones

unless UX context suggests otherwise.

==================================================
7. DARK MODE
==================================================

Dark mode must preserve the SAME identity.

Dark mode is NOT:

black background
+
gray cards
+
thin borders.

It must still have:

- strong tonal hierarchy
- visible surface layers
- rim definition
- directional light
- ambient shadow
- contact shadow
- near-white typography
- restrained orange accents

Dark mode should feel like physical dark objects under soft studio light.

It must NOT become:
- gaming UI
- cyberpunk
- neon
- glowing AI dashboard

==================================================
8. COMPONENT PHYSICALITY
==================================================

Not every component should be strongly 3D.

Use strongest tactile treatment for:
- hero objects
- milestones
- current bottlenecks
- important insights
- progress objects
- major selectors
- important interactive objects

Use quieter treatment for:
- ordinary list rows
- secondary metadata
- navigation
- low-priority information

This contrast makes important objects feel more physical.

==================================================
9. TYPOGRAPHY
==================================================

Typography creates hierarchy before color does.

English / Latin:
May use bold editorial display typography for major statements.

Chinese:
Must maintain the same authority and hierarchy,
but must NOT be artificially condensed to imitate Latin typography.

Same visual identity.
Different typographic mechanics.

Body content must always prioritize readability.

==================================================
10. NEGATIVE SPACE
==================================================

Do not fill empty space merely because space exists.

Negative space is an intentional part of the composition.

Use it to:
- isolate the dominant idea
- improve reading
- strengthen hero presence
- create calmness
- increase perceived quality

Minimal does NOT mean empty.

Detailed does NOT mean dense.

==================================================
11. MICRO-DETAIL
==================================================

The interface should feel crafted through small details.

Examples:
- subtle hover lift
- pressed state reducing elevation
- precise selected state
- contextual highlight
- carefully aligned icons
- fine edge definition
- smooth state transition
- meaningful microcopy

Do not add decoration merely to make the product look designed.

==================================================
12. AI PRESENCE
==================================================

Do not visually communicate AI through:
- purple gradients
- sparkle icons
- robot mascots
- glowing borders
- brain icons

AI intelligence should be perceived through:
- relevant insight
- personalization
- correct prioritization
- contextual feedback
- timing
- clarity

AI should feel intelligent without visually shouting "AI".

==================================================
13. PRODUCT-SPECIFIC RULE
==================================================

BECOMING is a language-learning and language-expression product.

The learner is the protagonist.
Their work is the evidence.
AI is the guide.

Therefore visual hierarchy should highlight:

LEARNER
↓
WORK
↓
INSIGHT
↓
PROGRESS
↓
AI SYSTEM

not:

AI
↓
analytics
↓
scores
↓
learner.

==================================================
14. VISUAL REFERENCE RULE
==================================================

When the approved Light/Dark visual boards are available,
use them as visual calibration references.

Do NOT ask:

"Does my layout look identical?"

Ask:

"Does my output have the same quality of..."

- contrast?
- physical depth?
- surface material?
- hero presence?
- typography authority?
- negative space?
- accent restraint?
- compositional confidence?
- craftsmanship?

==================================================
15. REQUIRED VISUAL REVIEW
==================================================

For every major UI implementation:

1. Implement.
2. Render the real UI.
3. Capture a screenshot.
4. Compare it with the approved BECOMING visual reference.
5. Identify the 3 biggest visual gaps.
6. Refine those gaps.
7. Render again.
8. Only then consider the visual work complete.

Do not report UI completion from code inspection alone.

==================================================
ANTI-PATTERNS
==================================================

Never default to:

- generic SaaS dashboard
- card grids everywhere
- nested cards
- low-contrast dark-on-dark surfaces
- flat border-only UI
- arbitrary shadows
- excessive gradients
- glass UI everywhere
- decorative AI styling
- equal visual weight everywhere
- excessive chart usage
- excessive visual density
- childish gamification
- styling every component differently

FINAL PRINCIPLE:

A BECOMING screen should feel COMPOSED, not assembled.

Important objects should feel PRESENT, not merely bordered.

The learner should feel UNDERSTOOD, not analyzed.
